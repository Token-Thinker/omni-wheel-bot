# owb-ui

The operator UI for Omni-Wheel Bot, written in Rust with
[Leptos](https://leptos.dev) (client-side rendering) and compiled to
WebAssembly. The bot serves it on first connect; it is a PWA, so the phone
can keep it afterwards.

## Building

```sh
cd owb-ui
trunk build --release      # or: just ui-build
```

Trunk writes `dist/`. A post-build hook in `Trunk.toml` renames the
content-hashed outputs to fixed names (`app.wasm`, `app.js`, `style.css`) so
the firmware's `include_bytes!` paths in `owb-bin/owb-esp/src/ui_assets.rs`
stay stable. `dist/` is checked in, so building the firmware does not need
Trunk; rebuild it after changing anything under `src/` or `assets/`.
`app.js` is wasm-bindgen glue generated by the build, not hand-written.

`trunk serve` (or `just ui-dev`) runs a local dev server, and
`just ui-check` type-checks the crate for `wasm32-unknown-unknown` without
Trunk.

## Layout

```
index.html                 Trunk entry point
assets/style.css           stylesheet (hand-written)
assets/manifest.json       PWA manifest
assets/icons/              PWA icons
src/lib.rs                 wasm entry point
src/app.rs                 root component; WebSocket URL + control-key resolution
src/transport.rs           WebSocket client with reconnect
src/throttle.rs            command rate cap + dedup
src/storage.rs             localStorage keys and helpers
src/components/            joystick, top strip, settings drawer
```

Wire types come from the shared `owb-msg` crate, so the UI and firmware cannot
drift apart on the command format.
